> Make every screen truly preschool-ready. Create all missing assets, build the voice pipeline, generate rich dummy task data, and run the full end-to-end validation before handing off for production.

## Part A — Design System & Global Stylesheet

### Step 1: Define the Master Color Palette
- [ ] Choose a curated, child-friendly color palette (no harsh/neon colors):
  - Primary: warm yellow/orange tones (buttons, highlights).
  - Secondary: soft sky blue (backgrounds).
  - Accent: playful pink/coral (hover states, celebrations).
  - Neutral: rounded greys for text, white for cards.
  - Danger/Alert: soft red-orange (never harsh red).
- [ ] Document the hex codes in `assets/design_system.md`.

### Step 2: Typography System
- [ ] Select a child-friendly font: **Nunito** (already in use) or **Baloo 2** / **Comic Neue**.
- [ ] Define font size scale for consistency:
  - Heading (question text): `42px`+, bold.
  - Sub-heading (task title): `32px`.
  - Body (instructions, speech text): `26px`.
  - Label (keyboard hints): `20px`.
- [ ] Ensure the font is bundled locally in `assets/fonts/` (no network dependency on the robot).

### Step 3: Global Stylesheet — `assets/styles.qss`
- [ ] Create a single QSS file that ALL screens import.
- [ ] Define reusable classes: `.card`, `.card-large`, `.btn-primary`, `.btn-secondary`, `.hint-label`, `.question-text`.
- [ ] All border-radius values should be large and rounded (30px+) for a friendly feel.
- [ ] All buttons should have generous padding (18px+) and minimum heights (70px+).

### Step 4: Apply the Stylesheet to Every Screen
- [ ] Load `styles.qss` once in `main.py` and apply to the entire `QApplication`.
- [ ] Audit every screen file and remove inline/hardcoded styles.
- [ ] Verify all screens render correctly with the shared stylesheet.

### Step 5: Dark Mode / Reduced Brightness Option
- [ ] Create an alternative "dim" stylesheet for low-light environments.
- [ ] Toggle with a keyboard shortcut (e.g., `D` key — visible only to teacher/admin).
- [ ] Dim mode uses muted tones and reduced contrast but keeps the same layout.

## Part C — Robot Eyes Animation System

### Step 21: Eye Widget — Base Component
- [ ] Create `core/robot_eyes.py` — a custom QWidget that draws two animated eyes.
- [ ] Default state: two round eyes with pupils, gentle idle blink every 3–5 seconds.
- [ ] Eyes should be scalable (work at different sizes across screens).

### Step 22: Eye Expressions — Happy
- [ ] Pupils dilate slightly, eyes curve into a smile shape (upside-down arcs).
- [ ] Used on: correct answer, celebration, greeting.

### Step 23: Eye Expressions — Thinking
- [ ] One eye squints slightly, pupils drift to upper-right (looking up).
- [ ] Used on: waiting for student answer (Evaluate screens).

### Step 24: Eye Expressions — Encouraging
- [ ] Soft, wide eyes with a slight tilt — warm and supportive.
- [ ] Used on: wrong answer, elaborate, explain screens.

### Step 25: Eye Expressions — Excited/Surprised

- [ ] Used on: student calling screen, before celebration.

### Step 26: Eye Expressions — Sleeping
- [ ] Eyes closed (two curved lines), occasional "Z" particle floats up.
- [ ] Used on: idle screen.

### Step 27: Eye Expressions — Gentle/Patient
- [ ] Half-lidded, calm expression.
- [ ] Used on: explain screen, teacher intervention.

### Step 28: Integrate Eyes Across All Screens
- [ ] Add the eye widget to every screen's layout (consistent position — top right or dedicated panel).
- [ ] Each screen triggers the appropriate expression on `showEvent`.
- [ ] Ensure eye transitions are smooth (animate from one expression to the next).

## Part D — Voice Pipeline Integration

### Step 29: Voice Manager — Refactor for Async
- [ ] Refactor `VoiceManager` so that voice generation and playback runs in a separate thread (prevent UI freezing).
- [ ] Use `QThread` or `threading.Thread` with a signal/callback on completion.
- [ ] UI should display the speech text while the audio plays.

### Step 30: Voice Manager — Pre-Cache Common Phrases
- [ ] Identify all static phrases that don't change per-task (greetings, encouragements, instructions).
- [ ] Pre-generate these audio files on first run and cache in `voice_cache/`.
- [ ] On subsequent runs, load from cache instantly.

### Step 31: Voice Manager — Dynamic Task Speech
- [ ] For task-specific speech (`speech_start`, `speech_end`, `task_description`), generate on-the-fly.
- [ ] Cache with a filename based on a hash of the text content.
- [ ] If the same text is used again, load from cache.

### Step 32: Voice Manager — Rate Adjustment per Affordance
- [ ] Level 1: normal rate (`rate="+10%"`).
- [ ] Level 2: slightly slower (`rate="+0%"`).
- [ ] Level 3: deliberately slow (`rate="-20%"`).
- [ ] Read the current affordance level from the State Manager and adjust automatically.

### Step 33: Voice Manager — Name Injection
- [ ] Create a helper that injects the student's name into speech text.
- [ ] At Level 3, prepend the name: _"[Name], listen carefully…"_
- [ ] At Level 1–2, use the name sparingly (only in celebration).

### Step 34: Voice Manager — Fallback (No Audio)
- [ ] If `edge_tts` fails or the system has no audio output, fall back to on-screen text only.
- [ ] Display a styled text bubble with the speech text.
- [ ] Log the audio failure but continue the session.

### Step 35: Speech Text Display Widget
- [ ] Create a reusable **Speech Bubble** widget that shows what the robot is "saying."
- [ ] Typewriter text reveal effect synchronized with audio playback.
- [ ] Placed consistently across all screens (bottom area or side panel).

## Part G — Accessibility & Child Safety

### Step 49: Prevent Accidental Key Spamming
- [ ] After a key press is registered, add a **300ms cooldown** before accepting the next press.
- [ ] Prevents excited children from accidentally double-pressing.

### Step 50: Prevent Unintended Exit
- [ ] Override the window close button (`closeEvent`) to show a confirmation.
- [ ] Require a special teacher-only key combo to close (e.g., `Ctrl+Q`).
- [ ] Prevent `Escape` from closing any screen or the app.

### Step 51: Screen Always-On / Fullscreen Mode
- [ ] Launch the app in fullscreen by default (`showFullScreen()`).
- [ ] Prevent the screen saver / display sleep while a session is active.
- [ ] Add a teacher shortcut to exit fullscreen (e.g., `Ctrl+F`).

### Step 52: Volume Control
- [ ] Implement a global volume slider stored in preferences.
- [ ] Accessible via a teacher shortcut (e.g., `V` key to cycle: low / medium / high / mute).
- [ ] All sounds (voice, effects, ambient) respect the global volume.
- [ ] Level 1 affordance: _"Sound volume is maintained at a comfortable, appropriate level."_

### Step 53: Repeat/Slow Down Control
- [ ] Allow repeating the current instruction by pressing `R` (Level 1 control affordance).
- [ ] Robot re-speaks the current speech text.
- [ ] If pressed twice rapidly, speak at a slower rate the second time.

## Part H — Performance & Optimization

### Step 54: Lazy Screen Loading
- [ ] Don't load all UI screens at app startup — load each screen on first navigation.
- [ ] Cache loaded screens in memory for instant revisits.
- [ ] Reduces startup time and memory footprint.

### Step 55: Audio Pre-Loading
- [ ] Pre-load common sound effects (`correct.mp3`, `bell.mp3`, `applause.mp3`) into memory on startup.
- [ ] Avoid disk reads during active interaction.

### Step 56: Image Memory Management
- [ ] For Level 2/3 affordance, larger images consume more memory.
- [ ] Implement image unloading when leaving a screen (release QPixmap references).
- [ ] Monitor memory usage in debug mode.

### Step 57: Thread Safety Audit
- [ ] Verify all Firebase calls run in background threads (not the main UI thread).
- [ ] Verify voice generation runs in a background thread.
- [ ] Ensure no UI updates happen from non-main threads (use signals/slots).
