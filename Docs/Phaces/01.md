# Phase 01 — Foundation & System Setup

> Establish the core project architecture, child-friendly UI skeleton, Firebase connectivity, and the idle/wake-up flow.

---

## Step 1: Project Structure Cleanup
- [ ] Reorganize the project into a clean folder structure:
  - `screens/` — all screen modules (evaluate, elaborate, engage, explain, explore, idle, teacher_select, greeting)
  - `ui/` — all `.ui` files moved here
  - `core/` — shared logic (firebase, voice_manager, robot_task, session state manager)
  - `Tasks/` — task JSON files (already exists)
  - `assets/` — images, sounds, fonts
- [ ] Update all `import` paths across the project to reflect the new structure.
- [ ] Verify the app launches successfully after reorganization.

---

## Step 2: Global Keyboard Manager
- [ ] Create `core/keyboard_manager.py` — a centralized keyboard event handler.
- [ ] Define a key mapping dictionary (e.g., `W` = wake, `A`–`Z` = option select, `S` = skip, `B` = break, `C` = continue).
- [ ] Allow screens to register/unregister their own key handlers so only the active screen receives input.
- [ ] Wire the keyboard manager into the main window's `keyPressEvent`.

---

## Step 3: Application State Manager
- [ ] Create `core/state_manager.py` to hold global session state:
  - `current_screen` (idle, teacher_select, greeting, evaluate, elaborate, etc.)
  - `selected_teacher`
  - `current_student`
  - `current_task`
  - `affordance_level` (1, 2, or 3)
  - `5e_stage` (evaluate, elaborate, explain, explore, engage)
- [ ] Expose getter/setter methods so all screens can read/update the state.

---

## Step 4: Firebase Backend Verification
- [ ] Verify the existing `firebase.py` Realtime Database connection works (fetch teachers, students).
- [ ] Add a Firestore client initialization alongside the existing Realtime DB connection (for future logging).
- [ ] Create a helper function `firebase.get_students(teacher_key)` to fetch the student list under a selected teacher.
- [ ] Create a helper function `firebase.log_event(data)` stub for Firestore logging (implementation comes in Phase 6).
- [ ] Test the connection by printing teacher and student data on launch.

---

## Step 5: Idle Screen — Design & Implementation
- [ ] Design the Idle Screen UI (child-friendly):
  - Full-screen, colorful background with soft animated elements (floating shapes, stars, etc.).
  - The robot name **"Akshi"** displayed prominently with a sleeping/idle animation (e.g., animated eyes blinking slowly).
  - A subtle text hint: _"Press W to wake me up!"_ (for dev purposes only).
- [ ] Create `screens/idle_screen.py` and the corresponding UI file.
- [ ] The screen should do nothing until the wake-up key (`W`) is pressed.

---

## Step 6: Wake-Up Transition & Greeting
- [ ] On pressing `W`, transition from the Idle Screen to a **Greeting Screen**.
- [ ] Greeting Screen shows:
  - Akshi's eyes "opening" with an animation.
  - A greeting message displayed on screen (e.g., _"Hello there! 🌟 I'm Akshi! Ready to learn something fun today?"_).
  - The robot speaks the greeting via `VoiceManager` (or prints to console for now).
- [ ] After a short delay (2–3 seconds), automatically transition to the **Teacher Selection Screen**.

---

## Step 7: Teacher Selection Screen — Redesign
- [ ] Redesign the existing `mainUI.ui` (Teacher Selection screen) to be child-friendly:
  - Remove the dropdown/combo-box entirely (not suitable for voice/keyboard-only interaction).
  - Instead, display teachers as large, colorful cards/buttons in a vertical list.
  - Each card shows the teacher's name and a keyboard shortcut label (e.g., `A`, `B`, `C`).
  - Bright background, rounded corners, playful font.
- [ ] Update `main.py` to fetch teachers from Firebase and dynamically populate the cards.
- [ ] On pressing the corresponding key (`A`, `B`, `C`, etc.), select that teacher and proceed.
- [ ] Robot speaks: _"Welcome! Let's pick your teacher. Press A for [Teacher 1], press B for [Teacher 2]…"_ (console print for now).

---

## Step 8: Main Window & Screen Stack Refactor
- [ ] Refactor `main.py` to use a proper screen management system:
  - Use `QStackedWidget` to hold all screens (Idle → Greeting → Teacher Select → and future screens).
  - Create a `navigate_to(screen_name)` function that switches the stack and updates the state manager.
- [ ] Register all Phase 1 screens in the stack: `idle`, `greeting`, `teacher_select`.
- [ ] Set the initial screen to `idle`.
- [ ] Ensure smooth transitions between screens (optional: fade-in/fade-out animation).

---

## Step 9: Integration Test — Full Phase 1 Flow
- [ ] Run the app end-to-end and verify the following flow:
  1. App launches → Idle Screen is shown.
  2. Press `W` → Greeting Screen appears, Akshi says hello.
  3. After delay → Teacher Selection Screen appears with teacher list from Firebase.
  4. Press `A` / `B` / `C` → Teacher is selected, printed to console.
- [ ] Fix any bugs or visual issues.
- [ ] Commit the working Phase 1 code.

---

**Total Steps: 9**
