# Phase 06 — Voice Module Integration, Research Tools & Deployment

> Bridge the keyboard-based development system to the production voice-controlled environment. Build research analytics tools, prepare deployment for the physical robot hardware, and finalize all documentation for the master's thesis.

---

## Part A — Voice Input Module (Speech Recognition)

### Step 1: Speech Recognition Library Selection
- [ ] Evaluate speech recognition options for preschool children's speech:
  - `speech_recognition` (Google/Whisper backend).
  - `vosk` (offline, lightweight).
  - `whisper` (OpenAI, high accuracy).
- [ ] Choose the library based on: accuracy with children's voices, offline capability (robot may not always have internet), and latency.
- [ ] Document the decision in `Docs/voice_module_decision.md`.

### Step 2: Microphone Input Setup
- [ ] Create `core/voice_input.py` — handles microphone listening.
- [ ] Detect available microphones and select the correct device.
- [ ] Implement a `listen()` function that captures audio until silence is detected.
- [ ] Configure noise threshold for classroom environments (multiple children, ambient noise).

### Step 3: Wake Word Detection
- [ ] Replace the `W` keyboard wake-up with voice activation.
- [ ] Implement a wake word listener: _"Hey Ginglu"_ or _"Hello Ginglu"_.
- [ ] Use a lightweight wake word engine (e.g., `pvporcupine` or keyword spotting with `vosk`).
- [ ] Keep the `W` key as a fallback for development/testing.

### Step 4: Speech-to-Text — Answer Recognition
- [ ] Implement `recognize_answer(audio)` that converts speech to text.
- [ ] Map recognized text to answer options:
  - For MCQ: listen for the option text (e.g., _"Left Hand"_, _"Right Arrow"_).
  - Also accept option numbers spoken aloud: _"one"_, _"two"_, _"three"_, _"four"_.
- [ ] Handle partial matches and common mispronunciations by preschoolers.

### Step 5: Confidence Threshold & Retry
- [ ] Set a confidence threshold for speech recognition (e.g., 0.7).
- [ ] If confidence is below threshold, robot asks: _"Sorry, I didn't catch that! Can you say it again?"_
- [ ] Allow up to 3 retries before treating it as "no answer" (same as timeout).
- [ ] Log every recognition attempt with the confidence score.

### Step 6: Voice Input — Teacher Name Selection
- [ ] Replace keyboard teacher selection with voice: _"Teacher [Name]"_.
- [ ] Match against the teacher list from Firebase (fuzzy matching for name variations).
- [ ] Keep keyboard fallback (`A`, `B`, `C`) active simultaneously.

### Step 7: Voice Input — Skip & Break Commands
- [ ] Recognize voice commands: _"skip"_, _"I want to skip"_, _"next"_ → trigger skip.
- [ ] Recognize: _"break"_, _"I need a break"_, _"stop"_ → trigger break.
- [ ] Recognize: _"continue"_ (teacher's voice) → resume from teacher intervention.

### Step 8: Voice Input — Repeat & Slow Down
- [ ] Recognize: _"repeat"_, _"say that again"_, _"what?"_ → repeat the current instruction.
- [ ] Recognize: _"slower"_, _"slow down"_ → re-speak at a reduced rate.

### Step 9: Dual Input Mode — Voice + Keyboard
- [ ] Create `core/input_manager.py` that abstracts input source.
- [ ] Both voice and keyboard feed into the same handler functions.
- [ ] A config flag switches between: `keyboard_only`, `voice_only`, `dual` (both active).
- [ ] The app should work identically regardless of input mode.

### Step 10: Voice Input — Noise Calibration Screen
- [ ] On first launch or teacher request, show a "Calibrate Microphone" screen.
- [ ] Record 5 seconds of ambient classroom noise.
- [ ] Set the noise floor threshold automatically.
- [ ] Store calibration data locally for future sessions.

## Part B — Research Data & Analytics Dashboard

### Step 11: Firestore Data Export Script
- [ ] Create `scripts/export_data.py` — exports all Firestore session data to CSV/JSON files.
- [ ] Separate exports: `sessions.csv`, `interactions.csv`, `student_summaries.csv`.
- [ ] Include all fields: timestamps, cascade paths, affordance levels, durations.

### Step 12: Per-Student Analytics
- [ ] For each student, calculate:
  - Total tasks attempted, correct on first attempt, correct after elaboration, correct after explain, etc.
  - Average affordance level reached.
  - Average time-to-answer per task.
  - Number of skips, breaks, teacher interventions.
- [ ] Export as `student_analytics.csv`.

### Step 13: Per-Task Analytics
- [ ] For each task, calculate:
  - First-attempt success rate.
  - Average affordance level needed.
  - Most common failure point in the cascade.
  - Average time spent.
- [ ] Export as `task_analytics.csv`.

### Step 14: 5E Model Effectiveness Analysis
- [ ] For each 5E stage (elaborate, explain, explore, engage), calculate:
  - How often the stage was reached.
  - Success rate after each stage (did elaboration help?).
  - Percentage of students who recovered at each stage.
- [ ] This is critical data for the master's thesis — proving the 5E model works.

### Step 15: Affordance Level Effectiveness Analysis
- [ ] For each affordance level (1, 2, 3), calculate:
  - Success rate at that level.
  - Average number of attempts before success.
  - Correlation between affordance level and student performance.
- [ ] Quantify: does increasing affordance improve outcomes?

### Step 16: Session Timeline Visualization Script
- [ ] Create `scripts/visualize_session.py` using `matplotlib`.
- [ ] Generate a timeline chart for each session:
  - X axis: time.
  - Y axis: students.
  - Color-coded blocks showing: evaluate, elaborate, explain, explore, engage, celebration, break, teacher intervention.
- [ ] Save as PNG image for thesis inclusion.

### Step 17: Student Progress Heatmap
- [ ] Generate a heatmap showing student × task performance.
- [ ] Rows: students. Columns: tasks.
- [ ] Cell color: green (L1 correct), yellow (L2 correct), orange (L3 correct), red (teacher intervention), grey (skipped).
- [ ] Save as PNG.

### Step 18: Cascade Depth Distribution Chart
- [ ] Bar chart showing how many interactions ended at each cascade depth:
  - Depth 1: Evaluate L1 (correct first time).
  - Depth 2: Elaborate → Evaluate L2.
  - Depth 3: Explain → Evaluate L3.
  - Depth 4: Explore → Evaluate L3.
  - Depth 5: Engage → Evaluate L3.
  - Depth 6: Teacher intervention.
- [ ] Essential for proving 5E model hypothesis in the thesis.

### Step 19: Automated Research Report Generator
- [ ] Create `scripts/generate_report.py` that produces a markdown report with:
  - Session metadata (teacher, date, student count).
  - All charts (embedded as images).
  - Key statistics and findings.
  - Raw data tables.
- [ ] Output to `reports/{session_id}_report.md`.

### Step 20: Statistical Significance Tests
- [ ] Implement basic statistical tests for the thesis:
  - Paired t-test: student performance with vs. without affordance adaptation.
  - Chi-square: independence between affordance level and success rate.
  - Effect size calculations (Cohen's d).
- [ ] Output results to the research report.
