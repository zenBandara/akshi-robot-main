# Phase 03 — The 5E Core Engine, All Screens & Affordance Levels

> This is the heart of the project. Build every screen of the 5E model (Evaluate, Elaborate, Explain, Explore, Engage), implement the full failure cascade, and adapt the Evaluate screen across all three Affordance Levels.

## Part A — Task Engine & JSON Infrastructure

### Step 1: Task JSON Schema Definition
- [ ] Define and document the official JSON schema for task files.
- [ ] Include all required fields: `task_id`, `task_name`, `description`, `engage`, `explore`, `explain`, `elaborate`, `evaluate`.
- [ ] Each 5E section must have: `task_title`, `speech_start`, `speech_end`, `description`.
- [ ] `evaluate` and `elaborate` must have: `task_type`, `task_description`, `multiple_choices_word`, `multiple_choices_images`, `correct_option`.

### Step 2: Task JSON Validator
- [ ] Create `core/task_loader.py` with a `validate_task(data)` function.
- [ ] Check that all required keys exist in the loaded JSON.
- [ ] Print clear error messages if any field is missing or malformed.

### Step 3: Task Loader — Load Single Task
- [ ] In `core/task_loader.py`, create `load_task(filepath)` to read and parse a single JSON file.
- [ ] Return the parsed dictionary after validation passes.
- [ ] Return `None` with an error log if validation fails.

### Step 4: Task Loader — Load All Tasks from Directory
- [ ] Create `load_all_tasks()` that scans the `Tasks/task_jsons/` directory.
- [ ] Load and validate every `.json` file found.
- [ ] Return a list of all valid task dictionaries.

### Step 5: Random Task Picker
- [ ] Create `pick_random_task(exclude_ids=[])` that selects a random task from the loaded pool.
- [ ] Accept an `exclude_ids` list to avoid repeating tasks already given in the session.
- [ ] Store the picked task in `state_manager.current_task`.

## Part B — Evaluate Screen (Level 1 Affordance — Low)

### Step 11: Evaluate Screen Layout — Level 1
- [ ] Design the Evaluate Screen UI for Level 1 (4 answer options).
- [ ] Layout: question text at the top, 4 large image cards in a 2×2 grid below.
- [ ] Each card shows the option image + text label + keyboard key label (1, 2, 3, 4).
- [ ] Background: clean, simple, minimal distractions (Level 1 physical affordance).

### Step 12: Evaluate Screen — Populate from Task Data
- [ ] Create `screens/evaluate_screen.py`.
- [ ] On screen load, read `state_manager.current_task["evaluate"]`.
- [ ] Set the question text from `task_description`.
- [ ] Set each option card's image from `multiple_choices_images` and label from `multiple_choices_word`.

### Step 13: Evaluate Screen — Robot Speech (Start)
- [ ] When the Evaluate Screen appears, the robot speaks `speech_start` from the task data.
- [ ] Use `VoiceManager.speak()` or print to console for now.
- [ ] Add a short delay after speech before enabling keyboard input (prevent accidental presses).

### Step 14: Evaluate Screen — Keyboard Input Handler
- [ ] Register the Evaluate Screen's key handler with the Keyboard Manager.
- [ ] Listen for keys `1`, `2`, `3`, `4` corresponding to `op1`–`op4`.
- [ ] On key press, highlight the selected card visually (border glow or color change).
- [ ] Disable further input after a selection is made.

### Step 15: Evaluate Screen — Answer Validation
- [ ] Compare the selected option with `correct_option` from the task data.
- [ ] If correct → trigger the **success path** (Step 18+).
- [ ] If incorrect → trigger the **failure path** (Step 25+).

### Step 16: Evaluate Screen — Pulse/Glow Animation on Options
- [ ] Apply a subtle pulse animation to the option cards to draw attention (Level 1 affective affordance).
- [ ] Refactor the existing `apply_pulse_glow()` function to be reusable across all screens.
- [ ] Move the animation utility to `core/animations.py`.

### Step 17: Evaluate Screen — Timer/Clock Widget
- [ ] Refactor the existing clock timer logic into a reusable `core/timer_widget.py`.
- [ ] Display a row of 🕒 emojis (or custom clock icons) that fade one by one.
- [ ] Configure total time (e.g., 20 seconds) and number of clock icons (e.g., 15).
- [ ] When time runs out, treat it as an incorrect answer and trigger the failure path.

## Part C — Success Path (Correct Answer)

### Step 18: Success Celebration Screen — Design
- [ ] Design a **Celebration Screen** shown when the student answers correctly.
- [ ] Big animated text: _"Amazing job, [Student Name]! 🎉🌟"_
- [ ] Confetti or star burst animation in the background.
- [ ] A cheerful sound effect plays (applause, cheer).

### Step 19: Success Celebration — Robot Speech
- [ ] Robot speaks an encouraging message: _"Wow, [Name]! You got it right! You're a superstar!"_
- [ ] Vary the message randomly from a pool of encouragement phrases to avoid repetition.
- [ ] Use `VoiceManager.speak()` or print to console.

### Step 20: Success Celebration — Gamified Reward
- [ ] Display a visual reward element (e.g., a gold star, a trophy, or animated sticker).
- [ ] Level 1 affective affordance: gamified reward after correct answer.
- [ ] Show the reward for 3–4 seconds.

### Step 21: Success Path — Log the Result
- [ ] Log the interaction to the State Manager:
  - Student ID, Task ID, result: `"correct"`, affordance level reached: `1`, path taken: `["evaluate_L1"]`.
- [ ] Call `firebase.log_event()` stub (actual Firestore write comes in Phase 6).

### Step 22: Success Path — Move to Next Student
- [ ] After the celebration, call `next_student()` (from Phase 2).
- [ ] If more students remain → show Student Calling Screen with the next student.
- [ ] If no students remain → show Session Complete Screen.

## Part K — 5E Flow Controller

### Step 53: Create the 5E Flow Controller
- [ ] Create `core/flow_controller.py` — the central state machine that manages the 5E cascade.
- [ ] Define the ordered cascade: `evaluate_L1 → elaborate → evaluate_L2 → explain → evaluate_L3 → explore → evaluate_L3 → engage → evaluate_L3 → teacher_intervention`.
- [ ] Maintain a pointer to the current position in the cascade for each student.

### Step 54: Flow Controller — `on_correct_answer()`
- [ ] Record the current position in the cascade as the resolution point.
- [ ] Trigger the success/celebration path.
- [ ] Reset the cascade pointer.
- [ ] Call `next_student()`.

### Step 55: Flow Controller — `on_incorrect_answer()`
- [ ] Advance the cascade pointer to the next stage.
- [ ] Determine what screen to show next (elaborate? explain? explore? engage? teacher?).
- [ ] Update the State Manager with the new `5e_stage` and `affordance_level`.
- [ ] Navigate to the appropriate screen.

### Step 56: Flow Controller — `on_skip()`
- [ ] Log the skip event with the current cascade position.
- [ ] Reset the cascade pointer.
- [ ] Call `next_student()`.
- [ ] Ensure this student won't be asked the same task again.

### Step 57: Flow Controller — `on_break()`
- [ ] Pause the cascade (do NOT reset the pointer).
- [ ] Show the break screen.
- [ ] On return from break, resume at the exact same cascade position.
- [ ] Do NOT mark the student as finished.

### Step 58: Flow Controller — `on_timeout()`
- [ ] Treat a timer expiry the same as an incorrect answer.
- [ ] Log the event as `"timeout"` instead of `"incorrect"`.
- [ ] Advance the cascade pointer.
